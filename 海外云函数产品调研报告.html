01核心结论

海外 Serverless 的竞争重心已从「有没有免费额度」转到「免费额度够不够跑生产」：三大云厂守住每月固定免费授予，Cloudflare 与 Vercel 用「请求数 + CPU 时长」双限额拉开发者，而 Railway、Fly.io 这类托管平台则选择收缩甚至取消永久免费层。计价单位的碎片化程度，已经成为比单价本身更重要的选型变量。

免费层分化为「云厂长期授予」与「平台试用」两类

三大云厂的免费授予都是长期口径且按账单账户计：AWS Lambda 每月 100 万次请求 + 40 万 GB-秒，Google Cloud Run functions 每月 200 万次调用 + 40 万 GB-秒 + 20 万 GHz-秒，Azure Functions 每订阅每月 100 万次执行 + 40 万 GB-秒。平台侧则是另一种形态——Cloudflare Workers 免费版每天 10 万次请求（约合每月 300 万次）、Vercel Hobby 每月 100 万次调用 + 4 小时 Active CPU，但都限定非商用或团队规模；Netlify 更彻底，Free 档只有每月 300 积分硬上限，用完项目直接暂停。判断一个免费层能不能上生产，关键看它是否有硬上限以及超限后的行为是「降级」还是「停机」。

计价单位在三家云厂之外高度碎片化

坚持「请求数 + GB-秒」两段式计价的只有 AWS Lambda、Azure Functions 与 Cloud Run functions；Cloudflare Workers 改为计「请求数 + CPU 毫秒」（$0.30/百万次 + $0.02/百万 CPU 毫秒），Vercel 计「调用次数 + Active CPU 小时 + 预置内存 GB-小时」，Netlify 把所有用量折成积分（计算 10 积分/GB-小时、带宽 20 积分/GB、Web 请求 2 积分/万次）再统一扣减，Render 与 Railway 干脆按实例常驻时长计费。这意味着「每月 100 万次免费调用」这类说法在平台型产品上根本无法直接比较——跨厂商比价的前提是先把自己的负载折算成对方的口径。

Railway、Fly.io 收缩免费层，边缘函数继续免费

Railway 的 Hobby 档 $5/月起、免费档只剩每月约 1 美元额度（第三方口径），Fly.io 自 2024 年 10 月起对新账户不再提供永久免费层——托管容器型平台的免费时代已经结束。与之相反，边缘侧仍在扩张：Cloudflare Workers 免费版每天 10 万次请求，Fastly Compute 免费层给到每月 1000 万次 Compute 请求，Deno Deploy 免费版每月 100 万次请求 + 20 GiB 出流量 + 20 小时 CPU。如果目标是零成本长期在线一个轻量服务，边缘函数是这张表里最现实的选项。

052024—2026 关键节点

按公开可查的发布、上线与计费调整时点排列，用于理解竞争格局是怎么形成的。

海外 Serverless 的这条时间线由两类事件交替构成：一类是免费层的收与放——Fly.io 在 2024 年 10 月停止对新账户提供永久免费层、Netlify 在 2026 年 4 月全面转向积分制并调整费率、Deno Deploy 在 2026 年 2 月正式 GA 并同时公布免费档；另一类是运行时与计费口径的重定义——Google 把 Cloud Functions 并入 Cloud Run 体系、Cloudflare 把 Workers 的计量从「请求数」扩展到「请求数 + CPU 毫秒」、IBM 把 Serverless 主线交给 Code Engine。综合来看，2024—2026 年不是价格战期，而是「计量方式重构期」：谁的口径更能反映真实成本，谁就更容易被写进架构方案。
